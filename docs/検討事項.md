## 2. 能力ポイントの総量・再配分ルール

**状態:** 未決

### 論点

「考えて勝つ」の中心が能力配分なのに、**何ポイント配れるか／後から変えられるか**が未定義。  
ポイント消費カーブ（高ステほど高い）も設計案から削除済みで、代替ルールも未定。

### 選択肢

| 案 | 内容 |
|----|------|
| **A** | 固定プール（例: 合計 100）。作成時に配分。以降はレース用の作戦だけ変更可 |
| **B** | 固定プール＋「リセット」は冷却時間または回数制限付き |
| **C** | レース勝利などでプールが増える（成長）。見た目報酬と分ける |

### 私案

**A を基本、B を緩和策。**  
C は「育成で強い個体を作る」に寄りやすく、ガチャ無しでもパワーインフレしやすい。  
まず **総ポイント数と各ステの上限** を仮決めし、8 頭対戦で触って調整するのがよい。

**仮提案（議論用）:**

- 配分可能ポイント: 80〜100
- 各ステ上限: 100（属性ボーナスで実効が上振れ可）
- 極端ビルドは可能だが、何かが必ず欠ける

### 私案２

**A に寄せつつ、ルールを一段具体化する（最優先で詰める項目）。**

消費カーブを復活させるより、次の方が説明しやすい:

| ルール | 仮 |
|--------|-----|
| **基礎値** | 全ステに同じ初期値（例: 各 30） |
| **配分プール** | 追加で振るポイント（例: 40） |
| **上限** | 各ステ 100（属性ボーナスは別枠で実効加算） |
| **再配分** | β は無料リセット可（デバッグ・調整優先）。正式版で B（冷却／回数）へ |

理由: 「高ステほど高い」は体感しにくい／説明コストが高い。基礎＋プールなら極端ビルドも残しつつ、最低限の万能性でレースが壊れにくい。  
**数値は仮。8 頭プロトで必ず触って直す前提。**

## 4. レース報酬（ガチャなしで何を渡すか）

**状態:** 未決

### 論点

能力はポイント配分で決める方針なので、報酬でステを直接強くしすぎない方がよい。  
一方、何も無いと「次のレース」以外の目的が薄い。

### 選択肢（組み合わせ可）

| 報酬種 | 内容 | 能力への影響 |
|--------|------|--------------|
| 見た目パーツ | 目・口・眉・ほっぺ | なし |
| 模様 | 属性・季節・イベント | なし |
| 称号・記録 | 連勝、特定脚質など | なし |
| 通貨 | 改名・スロット解放など | 間接のみ |
| 能力ポイント | プール増加 | **あり（要注意）** |

### 私案

**見た目・称号・記録を主報酬。能力ポイント増加はβでは入れない（またはごく少量）。**  
「同じ条件から作戦で勝つ」を守る。

### 私案２

**能力ポイント増加は β・正式とも「原則なし」に寄せる（私案より厳しめ）。**

| 渡す | 渡さない |
|------|----------|
| 表情・模様・称号・戦績 | ステ強化、ステ解放ガチャ |
| 改名チケット等の軽通貨（任意） | 勝たないと強くなるループ |

理由: 「ごく少量」は後からインフレの抜け穴になる。継続欲は **見た目と記録** で足りる設計に寄せた方が、いまの方針と一貫する。  
順位表・リプレイ視聴・脚質別成績など「見る報酬」も有効。

## 6. マッチングとレーティング

**状態:** 未決

### 論点

10 分サイクル＋受付は「同時開催のロビー」型。  
レーティングを入れると公平性は上がるが、待ち時間と実装が重い。

### 選択肢

| 案 | 内容 |
|----|------|
| **A** | レーティングなし。来た人＋CPU で 8 頭 |
| **B** | 簡易レート（勝ち越しで帯が変わる程度） |
| **C** | 本格 MMR マッチ（同レート帯優先） |

### 私案

**β は A。**  
人が少ないうちは C は成立しにくい。データが溜まってから B を検討。

### 私案２

**同意（β＝A）。「公平さ」はレート以外で出す。**

- 受付締切時の CPU 補充で常に 8 頭（設計案どおり）
- 戦績は見えるが、マッチ分けには使わない
- 実力差の不満が出たら、先に **練習** と **作戦フェーズの説明** を厚くする

B は同時接続が安定してから。C は長期見送りでよい。

## 13. 作戦フェーズで何をロックするか（新規）

### 選択肢

| 案 | 内容 |

### 私案２（この項目は新規のため主案）

**A 推奨。**

B は締切直前の最適化合戦になりやすい。C は厳しすぎて β の試行錯誤を阻害しうる。

## 18. スタート時の操作

**状態:** 未決（今後検討）

### 論点

一般的な競馬ゲームでは、ゲート開放のタイミングに合わせてボタンを押す形式が多い。  
本ゲームでは、**メトロノームのように左右に振れるゲージ**でスタート操作をする案を検討する。

### たたき台（未確定）

| 要素 | イメージ |
|------|----------|
| **UI** | 左右に振れるゲージ。中央に目標ゾーン |
| **操作** | 目標に近いタイミングで入力するほど良いスタート |
| **中央付近** | スタートタイミングが早く、スピード・心拍なども良い状態で出られる（案） |
| **目標から離れる** | スタートが遅れ、状態も悪化（案） |
| **振れが右側** | かかり気味で心拍などが大きくなりやすい？（案） |
| **振れが左側** | モチベーション下がり気味・スピード遅めのスタート？（案） |

#### 難易度・結果の補正（案）

| 条件 | 効果イメージ |
|------|----------------|
| **脚質が逃げ**／**スタートダッシュが高い** | ゲージの振れが **遅く止めやすい**。中央を外れても結果が **悪くなりにくい** |
| **スタートフェーズ中の目標スピードが高い** | ゲージが **早く振れる**。中央から離れたときのデメリットも **悪化**する |

- スタートフェーズでも **目標スピードを設定できる**（#17 の操作と接続）
- 「出脚を良くしたい／リスクを取る」トレードオフを、能力・脚質・ペース指示で表現する意図

※ 効果の種類・数値・左右の意味付け、補正のかかり方は **今後検討**。

| チュート／導入トライアル用の最小コース | **アプリ同梱**（オフライン必須） |
| 本番で使う基本コース一式（初期は少数） | **アプリ同梱**（β〜正式初期） |
| 大型スタジアム見た目・追加コース・季節版など重い追加 | **オンデマンド DL → 端末に保存（キャッシュ）**。以降はローカル利用 |

**やらない:** レース確定のたびにフル再ダウンロード（ストリーミングのみ）。  
更新があるときだけ差分／再取得。

※ DL の置き場所・マニフェスト形式は実装時。Steam／Play のストア容量と相談しながら同梱範囲を調整する。

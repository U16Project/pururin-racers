# CPUの強化学習（作りかけ・すべて仮）

Gran Turismo の Sophy と同じ考え方。人が決めるのは「何を見るか」と「何が良いか（点）」だけで、走り方はCPUが自分で見つける。
ゴドーに `client/` を開かせて、ここの台本を外から渡す。ゲーム本体には、ラボから起動したときだけ働く差し込み口を少し足してある（下の「ゲーム本体の差し込み口」）。

## 入れたもの（リポジトリの外）

- Python の仮の箱：`/media/u16/Backup/pururin-rl-venv/`（PyTorch・stable-baselines3・sb3-contrib・gymnasium・numpy）。中身はゲームと関係のない道具だけなので、ほかのゲームの育成にも使える
- ダウンロードの一時置き場：`/media/u16/Backup/pururin-rl-cache/`（消してよい）
- 入れ直すとき：`PIP_CACHE_DIR` と `TMPDIR` を上の一時置き場にしてから `pip install`（「/」の空きが少ないため）

## しくみ

- 1レース8席。出る8体は、レースごとに10体からくじで選ぶ。距離は5つ（`distances_m`）からくじ。
- 席ごとに3割（`trainer_swap.rate`）の確率で、トレーナーを15人からくじで選び直す（いつものトレーナーでない性格にも慣れるように。レース選択でトレーナーを変えたときに備える）。
- 席の内わけ（その育成のレース）：控え室からくじで2席（`pool.seats`）、分身1の最新版が1席（`pool.always_run`。分身1自身のレースでは無し）、のこりがその育成のCPU（学ぶ席）。
- 席は、オンラインで「通信ごしの人」が使うのと同じ入口（ライン・ノッチ・ブレーキ・ダッシュ・ブースト）で走る。操作は、ゲームの設定 `cpu_reaction_delay_s`（0.3秒）だけ遅れて届く（人の反応に合わせる。本番に入れるときも同じ値を使う）。
- 0.5秒ごとに、ゴドーが「見たもの（数字の並び）・点・選べる操作」を Python に送り、Python が操作を返す。返事を待つあいだ、ゲームの時間は止まる。
- 選べない操作（ブーストの残り0、ブレーキ中のダッシュ・ブースト、体力-100%でのダッシュなど、ゲームが受け付けないもの）は外す。場面ごとの決めごとは入れない。
- 見るもの：レースの状況・コースの先の形・流れ（先頭の速さ・隊列の長さ・集団の中の位置）・自分の値と能力・トレーナーの性格の数字（`lab/trainer_styles.json` の frame）・ほかの7体の値と能力・風よけ・押し合い。くわしくは `client/scripts/cpu_brain/brain_observe.gd`（ゲームと同じもの）。見るのは「今の様子」だけで、それまでに何をしたか（ブーストを押した場所など）は入っていない。そのため、点は、良い・悪いが決まったその場で渡す（下）。
- 点（`rl_settings.json` の `reward`）：ゴールの着順の点・1位とのタイム差の点・前へ進んだ分の小さな点・性格に合った走りの点。
  - 着順と1位とのタイム差はゴールで渡す。そのほかの点は、その場で渡す（2026-10-27から。ゴールでまとめて渡すと、どの判断の点か頭に伝わらず、本番3でブーストが早押しのまま直らなかった）。
  - 集団の得の点（`reward.group`。性格とは別）：前から風よけをもらっていた間に進んだ距離の割合 × draft ＋ 後ろから後方支援をもらっていた間に進んだ距離の割合 × rear。進むたびに少しずつ渡す。ふつうは0。
  - 体力温存の点（`reward.stamina`。減点だけ）：残り25%の線を越えたその時に、体力が目安（keep。20%、本番4は0%）より少なければ、足りない分 × per_short を引く。ふつうは0。
  - 性格の点（`reward.style`）：中ほどで性格の「いたい順位」にいた間に進んだ距離の割合 × place、後ろにつく・つかないが性格に合っていた間に進んだ距離の割合 × draft（どちらも進むたびに少しずつ）。ブーストは押したその時に、スタートから10%までなら opening_per_boost、ラスト25%なら spurt_per_boost、そのあいだは outside_per_boost。
- お手本：あなたがオフラインで走った記録（ふつうのレースも、play.py のレースも）のうち、`demo.since` より後のものを自動で取り込み、まねに寄せる（`demo`）。2026-10-26 20:36 より前の記録（スタートで無理に飛び出す相手と走ったもの）は使わない。前に作ったお手本は `runs/お手本_使わない_20261026/` に移した（戻せば、また使う）。
- 育て方：PPO（使えない操作を外せる版。sb3-contrib の MaskablePPO）。

- 上書きの設定は、初回に `--override` で渡すと `runs/<名前>/override.json` に写し、次からは自動で使う。
- 30分ごとの版は `runs/<名前>/versions/` と控え室に入る。`latest.zip` は10分ごとに上書き。

## 控え室（`runs/控え室/`）

- 保存したCPUを置いておき、どの育成のレースでも2席をくじで走らせる（学ばない）。`pool.from_runs` があれば、その育成の版だけをくじに入れる（本番1は本番1の版だけ）。`pool.plan` があれば、並べたものを1席ずつ走らせる（版の名前ならその版、`run:<育成>` ならその育成の古い版からくじ。本番4）。手で置いた .zip も相手役になる。消せば外れる。
- 上限20体（`pool.max`）。超えたら古いものから外す。名前の頭が「固定_」のものは外さない。
- 成績（相手役ごとに、本命より前を走った割合）は、育成ごとに `_成績_<育成>.json`。表とアドバイス：`pool.py`。
- 本命の席は学ぶために少しでたらめを混ぜて走るので、同じ強さでも相手役が6割くらい前に出る。版どうしの差を見る。
- ゲームの決まりを変えたら、変える前の版は外す（今の決まりでは走り方がずれている）。

## 人と走る・観戦する（`play.py`）

1. 起動すると「CPUを選ぶ画面」：いちばん上は、あなたの枠（最初は「あなた」。CPUにすると観戦）。相手1〜7は、レース選択で決まった相手の枠に、枠の順に当てはめる（最初は7枠とも本採用）。選べるのは、`runs/保存/` の本採用（`本採用_名前.zip`）と控え（`控え_名前.zip`）だけ。
2. ゲームのレース選択 → 出走表の「レース開始」。レース選択と出走表のトレーナー欄に、その枠を走らせるCPUの名前が出る。
3. レース中の順位表は「ミント［脚質1 20:27］」のように、どのCPUかが分かる。観戦では、追っている枠のCPUの操作盤とカメラが出る（一時停止はできる。走りの操作はCPUに届かない）。
4. 結果の板の「もう1回」は同じ選び方で次のレース、「戻る」とレース選択の「戻る」はCPUを選ぶ画面へ。
- ゲームパッド：上下で行、選ぶ欄は左右かAで切り替え、ボタンはA。

## ゲーム本体の差し込み口（ラボから起動したときだけ働く。ふつうに遊ぶときは何もしない）

| 場所 | 中身 |
|---|---|
| `RaceSession.race_starter` | 出走表の「レース開始」で、ふつうのレースの代わりにラボのレースを始める |
| `RaceSession.race_select_back` | レース選択の「戻る」で、ゲームのメニューの代わりにCPUを選ぶ画面へ |
| `RaceSession.slot_driver_label` | レース選択・出走表のトレーナー欄に、その枠を走らせるCPUの名前を出す |
| 走者の記録の `remote_controlled` | 記録ファイルで、育てるCPUの席（通信ごしに動く）とあなたを見分ける |
| `LocalRaceController._player_takes_input()` | 画面の「自分」が通信ごしに動く走者（観戦）のときは、ダッシュ・ブースト・ブレーキのキーを届けない |

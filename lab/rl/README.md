# CPUの強化学習（作りかけ・すべて仮）

Gran Turismo の Sophy と同じ考え方。人が決めるのは「何を見るか」と「何が良いか（点）」だけで、走り方はCPUが自分で見つける。
ゴドーに `client/` を開かせて、ここの台本を外から渡す。ゲーム本体には、ラボから起動したときだけ働く差し込み口を少し足してある（下の「ゲーム本体の差し込み口」）。

性格の正本は `client/data/config/cpu_trainers.json`。`lab/trainer_styles.json` は旧つまみ式ラボ用で、今の性格の正本ではない。

## しくみ

- 1レース8席。出る8体は、レースごとに16体からくじで選ぶ。距離は5つ（`distances_m`）からくじ。
- 席ごとに3割（`trainer_swap.rate`）の確率で、トレーナーを16人からくじで選び直す（いつものトレーナーでない性格にも慣れるように。レース選択でトレーナーを変えたときに備える）。
- 席の内わけ（その育成のレース）：控え室から `pool.plan` の数（本番6は4席）、のこりがその育成のCPU（学ぶ席）。
- 席は、オンラインで「通信ごしの人」が使うのと同じ入口（ライン・ノッチ・ブレーキ・ダッシュ・ブースト）で走る。操作は、ゲームの設定 `cpu_reaction_delay_s`（0.3秒）だけ遅れて届く（人の反応に合わせる。本番に入れるときも同じ値を使う）。
- 0.5秒ごとに、ゴドーが「見たもの（数字の並び）・点・選べる操作」を Python に送り、Python が操作を返す。返事を待つあいだ、ゲームの時間は止まる。
- 選べない操作（ブーストの残り0、ブレーキ中のダッシュ・ブースト、体力-100%でのダッシュなど、ゲームが受け付けないもの）は外す。場面ごとの決めごとは入れない。
- 見るもの：レースの状況・コースの先の形・流れ（先頭の速さ・隊列の長さ・集団の中の位置）・自分の値と能力・トレーナーの性格の数字（`client/data/config/cpu_trainers.json` の `frame`）・ほかの7体の値と能力・風よけ・押し合い。くわしくは `client/scripts/cpu_brain/brain_observe.gd`（ゲームと同じもの）。見るのは「今の様子」だけで、それまでに何をしたか（ブーストを押した場所など）は入っていない。そのため、点は、良い・悪いが決まったその場で渡す（下）。
- 点の重さの正本は `rl_settings.json` の `reward`。共通の着順・タイム差・ゴール／走行中の引き点・心拍・前進・ブースト時期は継続する。`style` はブースト時期だけを持つ。
- 性格の点は `reward.personality` の重さ × `cpu_trainers.json` の `frame` の数字。毎こま、進んだ距離に応じて `_owe` に積み、次の判断へ渡す。
  - `stick`（こだわり）：スタート〜`stick_until` の区間。走者自身の `running_style` に対応する `place_by_style` の順位範囲にいた距離は加点、外は減点。どちらもこの区間の全長で割る。トレーナーの得意脚質は使わない。
  - `draft`（ドラフト）：`received_draft_p >= draft_at_least` だった距離 ÷ レース全長。
  - `rear`（後押し）：`rear_assist_air_factor > 0` だった距離 ÷ レース全長。
  - `contact`（接触）：`get_contact_count() > 0` だった距離 ÷ レース全長。性格の数字が負なら減点。
  - `steady`（マイペース）：実際に変わったノッチの段数と、動けたライン操作の回数ごとに `steady_per_change` を引き、1走の減点の大きさは `steady_max` まで。その後で性格の数字を掛ける。ラインは届いた方向操作1回につき、実際に動いた最初のこまだけ数える。同じ方向を次の判断でも選べば別の1回。壁・相手に止められて不動の操作、押し出された距離は数えない。
  - `keep`（温存）：`keep_at` の25/50/75%を通過したこまの `max(体力割合, 0)` に、重さを3等分して掛ける。未到達の地点は払わない。
- 削除した共通の `group`、旧 `style.place/draft` と中ほどの区間設定、75%地点の `stamina` 減点は使わない。古い上書き設定を渡すとエラーにする。
- お手本：あなたがオフラインで走った記録（ふつうのレースも、play.py のレースも）のうち、`demo.since` より後のものを自動で取り込み、まねに寄せる（`demo`）。2026-10-26 20:36 より前の記録（スタートで無理に飛び出す相手と走ったもの）は使わない。
- 育て方：PPO（使えない操作を外せる版。sb3-contrib の MaskablePPO）。

## 控え室（`runs/控え室/`）

- 保存したCPUを置いておき、どの育成のレースでも2席をくじで走らせる（学ばない）。`pool.from_runs` があれば、その育成の版だけをくじに入れる。`pool.plan` があれば、並べたものを1席ずつ走らせる（版の名前ならその版、`run:<育成>` ならその育成の古い版からくじ）。手で置いた .zip も相手役になる。消せば外れる。
- 上限20体（`pool.max`）。超えたら古いものから外す。名前の頭が「固定_」のものは外さない。
- 成績（相手役ごとに、本命より前を走った割合）は、育成ごとに `_成績_<育成>.json`。表とアドバイス：`pool.py`。
- 本命の席は学ぶために少しでたらめを混ぜて走るので、同じ強さでも相手役が6割くらい前に出る。版どうしの差を見る。
- ゲームの決まりを変えたら、変える前の版は外す（今の決まりでは走り方がずれている）。

## 人と走る・観戦する（`play.py`）

1. 起動すると「CPUを選ぶ画面」：いちばん上は、あなたの枠（最初は「あなた」。CPUにすると観戦）。相手1〜7は、レース選択で決まった相手の枠に、枠の順に当てはめる（最初は7枠とも、`rl_settings.json` の `play_run`（設定の名前）の最新の版。まだ版が無ければ本採用）。観測2に合わない旧いCPUを選ぶと、レース開始前に拒否する。選べるのは、`runs/保存/` の本採用（`本採用_名前.zip`）と控え（`控え_名前.zip`）と、育成中の最新（`runs/<育成の名前>/versions/` のいちばん新しい版。レースを始めるたびに読み直す）。
2. ゲームのレース選択 → 出走表の「レース開始」。レース選択と出走表のトレーナー欄に、その枠を走らせるCPUの名前が出る。
3. レース中の順位表は「ミント［安定版］」のように、どのCPUかが分かる。観戦では、追っている枠のCPUの操作盤とカメラが出る（一時停止はできる。走りの操作はCPUに届かない）。
4. 結果の板の「もう1回」は同じ選び方で次のレース、「戻る」とレース選択の「戻る」はCPUを選ぶ画面へ。

## 動かし方（リポジトリのいちばん上で）

```bash
# 育成（止めるときは Ctrl+C。それまでのCPUは保存される。--games は同時に動かすゲームの数）
# 新しい性格の育成は上のコマンドを使う。旧い頭から --resume しない。
# ゲームのCPUに書き出す（最新から：--run 本番6、保存した版から：--file lab/rl/runs/保存/本採用_性格.zip）
/media/u16/Backup/pururin-rl-venv/bin/python lab/rl/export_brain.py --file lab/rl/runs/保存/本採用_性格.zip
# 人と走る・観戦する
/media/u16/Backup/pururin-rl-venv/bin/python lab/rl/play.py
# 控え室の成績の表と、管理のアドバイス
/media/u16/Backup/pururin-rl-venv/bin/python lab/rl/pool.py
# 使った・外したお手本の記録の表
/media/u16/Backup/pururin-rl-venv/bin/python lab/rl/demos.py
# つなぎの確かめ
/media/u16/Backup/pururin-rl-venv/bin/python lab/rl/check.py
```

- 育成レースの記録は `runs/<名前>/race_logs/`。頻度と保持数は `lab/rl/rl_settings.json` の `train.race_log_every`・`train.race_log_keep` で決める（現在は100レースに1本、最新30本）。`rl_race.gd` が全員の状態を記録する。
- 進み具合は `runs/<名前>/progress.csv`。`report_every_races` ごとの区間を集計し、ターミナルにも日本語の表で同じ内容を出す。点は**学ぶ席の1走あたりの平均**（相手役を除外）。着順・1位とのタイム差の加点・ゴール差の減点・走行中の差の減点・心拍・ブースト時期・性格6項目をそれぞれ記録する。前進の点と合計も記録し、内訳を照合できる。
- 実際の走りは、順位組にいた距離割合（0〜80%区間を分母）、ドラフト・後押し・接触の距離割合（レース全長を分母）、実際のノッチ変更段数・ライン変更回数、25/50/75%地点の体力割合を出す。未到達の体力はCSV空欄・表では「—」。
- 各項目でトレーナーの数字が高い組（0.6以上）と低い組（0.2以下）を分け、対応する実際の走りの平均と標本数を並べる。接触だけ高0.5以上／低−0.3以下。マイペースはノッチ・ラインを別々に、温存は3地点を別々に比較する。該当する走者がいなければ0とせず空欄にする。数字は1が100%。組ごとの平均は能力・脚質・展開の影響も受けるため、単独で学習効果を断定しない。
- 削除した仕様の記録列は廃止。既存のCSVを開く際は項目名で列を移し、過去の行の新項目は空欄にする。育成の起動だけで過去の走行を再計算することはない。
